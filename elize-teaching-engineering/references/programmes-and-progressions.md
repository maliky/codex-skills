# Programmes and Progressions

Use this reference when extracting official programme content, assigning capacity codes, comparing programmes, or building an annual or period progression.

## Source Boundary

- Treat official `BO_*.pdf` files and maintained `bo_*.org` transcriptions as protected sources. Preserve their wording, order, spelling, accents, and faults exactly.
- Never overwrite, annotate, regenerate, normalize, or silently correct a protected source. Put extracts, corrections, paraphrases, thematic reorganizations, and teaching adaptations in clearly named derived files.
- Reproduce a citation verbatim and label a paraphrase as a paraphrase. When the PDF and Org transcription diverge, record the exact divergence and ask before changing either source.
- Record available provenance such as title, date, BO number, NOR reference, and URL. A repository copy is evidence, not proof that a regulation is still current.

## Select the Teaching Surface

- Read the current timetable and repository layout before choosing levels or groups. Do not infer the present teaching assignment from old folders or prior sessions.
- Keep student rosters, administrative folders, and personal correspondence confidential. Use class or group identifiers in reports unless individual data is required for the task.
- Counts such as weeks, sessions, or capacity codes are derived invariants for a particular source set. Recompute them rather than treating remembered values as constants.

## Derive a Progression

1. Inventory the programme themes, contents, capacities, transversal expectations, and stated dependencies without changing source order.
2. Define stable codes in the derived document when repeated references need them; retain a readable mapping back to the exact programme wording.
3. Build the calendar from the actual teaching weeks and session structure. Make spiralling, prerequisites, assessment points, and revisits explicit teaching decisions rather than claims about the official text.
4. Link every planned block to defined capacities and identify capacities that are uncovered, referenced before introduction, or only assessed implicitly.
5. Separate confirmed source facts, archive-derived patterns, proposed sequencing, and unresolved choices.

## Validation

- Parse the changed Org files noninteractively when possible.
- Check duplicate and undefined codes, required columns, chronological sequence, expected blocks per week, and full capacity coverage.
- Review the first occurrence and later reinforcement of each capacity; raw reference coverage does not prove a coherent progression.
- If comparing programmes, neutralize formatting noise for the analysis but leave both source witnesses unchanged. Label conclusions as confirmed, moved, reformulated, absent, or uncertain according to the evidence.
